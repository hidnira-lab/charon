# A7 · 断网保护 (Kill Switch)、开机行为与紧急释放工具

Charon 的断网保护仅在隧道**意外中断**时拦截流量。当你自己点击 `断开连接` 时，断网保护不会拦截流量。

## Windows 上的工作原理 (`WIN2`, `WIN3`, `WIN5`)

在 Windows 上，`CharonService` 后台服务使用专属 Provider GUID 管理持久化的 Windows 过滤平台 (WFP) 规则：

* **Disarmed（已解除）**: 无 WFP 拦截规则，流量直连。
* **Armed（已启用）**: 仅允许通过 `charon0` Wintun 虚拟网卡、Xray 进程本身、本地环回、建立连接所需的 DHCP/DNS、局域网（开启 `允许局域网` 时）以及你配置的直连分流规则。
* **Held（已拦截）**: 当 Xray 意外退出、`charon0` 网卡消失（`SM1`）或所有服务器均重试失败进入 `已拦截`（`Blocked`）时，过滤器保持在 `Held` 状态，阻止普通外网流量离开电脑，直到你点击 `立即重试`、`选择其他服务器` 或 `解除拦截`。

### 开机恢复矩阵 (`SM2`)

当 Windows 重启时，后台服务会检查上一次会话结束时是否处于已连接状态：

| 上次会话是否已连接？ | 断网保护 | 自动重连 | Windows 开机时的行为（登录前） |
| --- | --- | --- | --- |
| 否（手动断开） | 任意 | 任意 | 保持 `Idle` 与 `Disarmed`。 |
| 是 | 开 | 开 | 在你登录前自动启用 WFP 过滤器并重新连接。 |
| 是 | 开 | 关 | 启用 WFP 过滤器并进入 `已拦截`（`Held`），等待你的操作。 |
| 是 | 关 | 开 | 不安装 WFP 过滤器，自动重新连接。 |
| 是 | 关 | 关 | 保持 `Idle` 与 `Disarmed`。 |

### 紧急释放过滤规则 (`charon-release.exe`)

由于 WFP 过滤规则在重启后仍然保留，如果后台服务在 `Held` 状态下未能启动，网络可能保持被拦截状态。你可以随时移除所有 Charon 过滤规则：

* 在 `Charon 服务未运行` 界面点击 `打开释放工具`，或
* 以管理员身份运行安装目录中的 `charon-release.exe`。

## Android 上的工作原理 (`CORE3`, `CORE6`)

* 当处于 `Held`（`重连中` 或 `已拦截`）状态时，Charon 会保持 `VpnService` 的 TUN 接口处于打开状态，防止流量回退到蜂窝网络或 Wi-Fi，同时显示红色的 `流量已拦截` 前台通知（附带 `立即重试` 与 `解除拦截` 按钮）。
* **Android 平台限制说明**: 如果 Android 系统终止了 Charon 进程或手机重启，在未开启系统级锁定的情况下流量可能会直连。若需完整保护，请前往 Android `设置 > 网络和互联网 > VPN > Charon`，同时开启 **始终开启的 VPN (Always-on VPN)** 和 **屏蔽未通过 VPN 的连接**。
